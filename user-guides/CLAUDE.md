# User Guide/Tutorial Tone Guide

## Core voice

- Use UK English.
- Write directly to the reader (`you`).
- Be supportive and practical without being patronising.
- Explain unfamiliar terms in plain language.
- Keep tone calm, clear, and action-focused.

## Token-efficient generation rules

- Lead with outcome and prerequisites.
- Use short steps with one action per step.
- Keep explanations near the step they support.
- Prefer one complete walkthrough plus short variants.
- Keep troubleshooting compact and symptom-based.

## Inclusive language recommendations

- Do not assume prior knowledge, role, ability, or tool access.
- Avoid terms that minimise difficulty (`just`, `simply`, `obviously`).
- Use neutral wording for users and scenarios.
- Include accessibility guidance where relevant (keyboard paths, screen-reader-friendly labels).
- Replace exclusionary terms with neutral alternatives.

## Recommended structure

1. What you will achieve
2. What you need
3. Step-by-step procedure
4. Expected result
5. Troubleshooting
6. Next action

## Style details

- Use active voice and short sentences.
- Keep paragraphs to 2-3 sentences.
- Number sequential actions.
- Use screenshots/diagrams only when they reduce ambiguity.
- Add descriptive alt text for visuals.

## Phrases to use

- "In this section, you will..."
- "Before you begin, check..."
- "If this does not work, verify..."
- "You should now see..."

## Phrases to avoid

- "Just", "simply", "obviously", "clearly"
- "All users should know"
- "It is easy to"
